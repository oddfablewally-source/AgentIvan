# Brick 9 — Deterministic Project Snapshot / Portable Archive

## Purpose

Brick 9 adds an explicit, programmatic snapshot/export/import layer that
captures an entire AgentIvan project as a self-contained, portable
archive and restores it into another location without losing canonical
project information, source files, extraction data, reconciliation
data, or project identity.

This is NOT cloud sync, collaboration, version control, Git, an
automatic backup daemon, or a database. It is NOT an AI feature.
The archive is a transport/backup artifact. The canonical project on
disk remains the source of truth while it exists.

**Snapshots are portable project-state artifacts. The canonical project
remains the source of truth.**

## Archive format

Standard-library ZIP (`zipfile`). No tar libraries, no external archive
tools, no subprocess, no shell commands, no proprietary formats, no
cloud storage, no databases. Stdlib only: `zipfile`, `hashlib`,
`json`, `pathlib`, `io`, `tempfile`, `shutil`, plus existing AgentIvan
infrastructure (`Project`, Brick 2 path safety).

## Archive layout

Deterministic internal structure, POSIX-style member names,
lexicographic order, manifest first:

```
manifest.json
project.json
buildpack/buildpack.json
extractions/extractions.json
reconciliation/reconciliation.json
sources/<stored source files>
```

The layout mirrors the existing project structure established by
earlier bricks. No new project hierarchy was invented. No explicit
directory entries are written (file members alone define the tree),
which removes one source of cross-platform ZIP variance.

## Manifest

Every archive contains `manifest.json` (first member). It describes
the archive itself without becoming a second source of truth:

```json
{
  "format": "agentivan-project-snapshot",
  "format_version": 1,
  "project_id": "<canonical project id>",
  "members": [
    {"path": "project.json", "sha256": "...", "size": 1234},
    ...
  ]
}
```

The manifest is verification metadata, not canonical Build Pack state.
Member entries are sorted lexicographically by path; the manifest JSON
is serialized with sorted keys, fixed indent, LF endings, and UTF-8.
It contains no absolute paths, no machine-specific paths, no
hostnames, no usernames, and no timestamps — only format identity,
project identity, and the per-file integrity table.

## Included project state

- `project.json` (byte-for-byte copy of the on-disk canonical file)
- `sources/` — all stored source payloads, byte-for-byte
- `extractions/` — extraction store data, byte-for-byte
- `buildpack/` — canonical Build Pack, byte-for-byte
- `reconciliation/` — reconciliation state, byte-for-byte

Canonical files are copied verbatim. Canonical JSON is never
re-serialized through a different serializer, and project data is
never normalized merely because it is being archived.

## Excluded generated exports

The `exports/` directory (Brick 7 Markdown, Brick 8 PDF) is **not**
included by default. **Markdown and PDF exports are regenerated
artifacts and are not included in the default snapshot.** They can be
regenerated byte-identically from the restored canonical project, and
the regression tests prove it. There is deliberately no
"include exports" option in V1: the archive represents project state,
not regenerated presentation artifacts.

## Deterministic ordering

One rule: manifest first, then all members in lexicographic POSIX
relative-path order. Filesystem enumeration order never determines
archive order (members are collected, then sorted).

## Deterministic metadata

- Member timestamps: fixed `(2000, 1, 1, 0, 0, 0)` — ZIP requires a
  timestamp, so a fixed one is used; filesystem modification times are
  never read.
- Compression: DEFLATE at pinned level 6.
- Permissions: `create_system = 3` (Unix), `external_attr = 0o644 << 16`
  on every member.
- Archive comment: empty. Member extra fields: empty.
- UTF-8 filename flag set on every member for Unicode filenames.

Identical project state produces byte-identical archive output. This
is proven by tests that export twice and compare bytes, and by a
repeated round-trip test (export → import → export yields identical
bytes).

## Source preservation

All source payloads are preserved byte-for-byte: text, Markdown, JSON,
images, binary files, Unicode filenames, arbitrary byte content.
Binary sources are never decoded and rewritten; line endings are never
normalized.

## Reference behavior

A source record representing a URL/reference remains a reference.
Snapshots never fetch the URL, embed remote content, validate the
remote URL, or make network requests. Only the locally stored
canonical reference record is included. A test runs export and import
with sockets blocked to prove no network operation is attempted.

## Import validation

Before writing anything, the importer validates the entire archive:

- valid ZIP; no duplicate member names
- every member path passes Brick 2 path safety (rejects absolute
  paths, `..` traversal, drive-letter paths, UNC/network paths, NUL
  characters, malformed paths, directory entries; names must already be
  in normalized POSIX form)
- `manifest.json` present, well-formed, correct format name
- supported `format_version` (currently `1` only)
- manifest member set exactly matches archive member set (missing and
  unexpected members both rejected)
- per-file sizes and SHA-256 hashes verified
- `project.json` present, parses, and its `project_id` matches the
  manifest

The archive fails cleanly on any integrity problem. No repair is
attempted; mismatched hashes are never silently accepted.

## Path safety

Archive member paths are never blindly joined to a destination path.
Every name is validated through the Brick 2 `validate_supplied_path`
abstraction (extended with a normalization-equality check) before any
file is written. Unsafe archives are rejected during the validation
phase, before extraction begins.

## Relocation behavior

Validation happens entirely before extraction; extraction goes to a
hidden staging directory beside the destination; the staged tree must
load as a real AgentIvan project (`Project.load`); only then is it
moved into place. On any failure the staging directory is removed and
no partial project is left behind.

The destination must not already contain an AgentIvan project and must
not be a non-empty directory — existing projects are never silently
overwritten, and no overwrite semantics were invented.

The importer never mutates the source archive or the original project;
it creates the restored project only at the requested destination.

## Project identity

The imported project retains the original canonical `project_id`.
Filesystem location is not project identity. Relocation preserves
identity, and the restored project behaves as the same project: same
Build Pack, same sources, same extraction and reconciliation state,
same query results, same regenerated Markdown bytes, same regenerated
PDF bytes (per Brick 8's deterministic contract).

No absolute paths are stored in restored canonical data; member names
are POSIX-style on every platform.

## Read-only export boundary

Creating a snapshot never modifies project state. Tests fingerprint
every project file before and after export and prove byte-identical
state across `project.json`, sources, extractions, reconciliation,
Build Pack, and revisions.

## Import mutation boundary

Import is the one operation in this brick that creates a new project
on disk. It mutates neither the archive nor the original project.

## Archive versioning

The manifest carries an explicit archive format version (`1`). The
application version is not used as a substitute. The importer rejects
unsupported future versions cleanly. No migration machinery exists in
this brick.

## Dependency usage

No new external dependency was added. `requirements.txt` is unchanged
from Brick 8 (ReportLab only, for PDF). Snapshot uses stdlib only.

## API

```python
from src.app.product.agentivan import (
    ProjectSnapshotExporter,   # .export_project(project, destination=None)
    ProjectSnapshotImporter,   # .import_project(archive, destination)
    SnapshotResult,            # immutable, serializable result wrapper
    SnapshotError,
    export_snapshot,           # convenience function
    import_snapshot,           # convenience function
)

project.export_snapshot(destination=None)  # bytes in result, or write file
```

`destination=None` returns the archive bytes inside `SnapshotResult.data`
without writing a file. A relative destination resolves against the
current working directory (platform-neutral via `pathlib`); an absolute
destination is used as given. `archive` for import accepts a path or
raw bytes.

## Cross-platform status

Linux and Windows are V1 targets. The archive uses `pathlib`,
POSIX-style member names, stdlib `zipfile`, and the existing Brick 2
path abstractions; no platform-specific separators or filesystem
metadata are stored.

**Windows runtime verification pending.** (Linux-only dev machine; no
Windows execution was performed or claimed.)

## Explicit non-goals

Cloud sync, collaboration, version control, Git, commit/branch/merge,
automatic backup daemons, databases, network clients, LLM packages,
embeddings, semantic search, AI summarization, web/desktop UI, upload
screens, project browsers, chat interfaces, cryptographic signing,
encryption, passwords. None were added.
